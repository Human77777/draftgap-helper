# DraftGap Helper · 阵容助手

Windows 本地工具：点击一次，读取当前世界赛已公布的英雄并填入 DraftGap，未选位置留空；十人齐全后自动打开 Draft Analysis。独立伴随工具，使用 DraftGap 内部接口，目前作为测试版使用。

项目地址：[Human77777/draftgap-helper](https://github.com/Human77777/draftgap-helper)。原创代码沿用仓库的 [MIT 许可证](LICENSE)，第三方来源见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。

双击 **启动助手.cmd**，打开带右下角填入面板的专用 DraftGap 窗口。开局后点击 **读取当前比赛并填入**，才获取一次双方阵容并填入。首次启动需要等待 DraftGap 自己加载数据。需要本机已有 Node.js 22+ 和 DraftGap；无第三方 npm 依赖。

每次点击直接读取 https://lolworlds2026.com/ 的当前直播区，按上单、打野、中单、ADC、辅助填入；蓝方放左边“我方”，红方放右边“对方”。有 1–9 个英雄也能录入，未选位置清空并留在 Draft；十人齐全后自动打开 Draft Analysis。部分阵容缺少明确槽位时，会额外读取当前比赛的选手分路表来定位，避免把后面的英雄向前挤。没有任何英雄、网络错误或页面结构无法识别时，保留现有阵容并显示提示。需要更新时再次点击，不会自动重试或追踪下一局。

已取消自动检测和周期定时器。为绕过网页跨域限制，需要保留一个只响应按钮事件的本地 Node 连接进程；空闲时不抓取网站、不循环检查 DraftGap。主要减少后台 CPU 和网络活动，内存节省有限。关闭专用 DraftGap 窗口时连接进程随调试连接关闭而退出。不注册系统服务、不配置开机启动。

**时效边界：本插件不需要等待比赛结束或十人选满，但只能录入源站已经公布的英雄，无法保证开局零秒同步。源站自身的数据发布和缓存延迟不受插件控制。当前接入仅覆盖该网站跟踪的世界赛，不是所有联赛。**

手动模式按上单、打野、中单、ADC、辅助顺序填写双方英雄，用逗号分隔。点击“检查”预览，再点击“手动填入”。支持常见中文名、别名、Riot 官方英雄称号、英文英雄名及数字 ID；联网读取使用随附的 173 英雄字典。未收录的中文俗称请用英文或数字 ID；插件会明确报错，不猜测英雄。空位填 `-`。

## 对话助手或命令行填入

启动插件后，在此目录执行：

```powershell
node launcher.mjs --apply example.json
```

JSON 使用 `ally`、`opponent` 两个字符串，格式见 example.json。每次填入前检查重复英雄、五个位置和客户端接口；填入后核对实际英雄 ID 与分路，失败时尝试恢复先前阵容。保留已有禁用英雄，不自动推断截图未提供的 ban。

## 版本与工作方式

这是本地伴随插件，通过 WebView2 的本地调试接口调用 DraftGap 自带的 `DRAFTGAP_DEBUG.pickChampion`，无需改动安装目录或游戏客户端。调试端口仅配置在本机回环地址；关闭专用 DraftGap 窗口即结束这次调试服务。专用配置保存在 `.runtime/webview-profile`，原来 DraftGap 的个人设置不会自动复制过来。

统计版本沿用 DraftGap 当前数据。**没有 26.20 历史数据，当前不能回退到 26.20，也不会把现有数据冒充为 26.20。** 程序版本降级与统计补丁版本不同。

如果提示接口不存在，可能是上游改变了内部接口或数据没有加载完成。报错会写入 `.runtime/error.log`。在专用窗口加载完成后重试；也可指定安装位置：`node launcher.mjs --exe "C:\Program Files\DraftGap\DraftGap.exe"`。

运行检查：`npm run check`、`npm test`（无 npm 依赖，无需 npm install）。最近一次读取状态与诊断保存在 `.runtime/live-status.json` 和 `.runtime/manual-read.log`。

已在本机安装的 DraftGap 上完成端到端验证：启动专用窗口、注入助手面板、按需联网抓取并填入，核对实际英雄 ID 与分路。自动检查覆盖解析、直播区样本、未齐阵容、重复英雄、旧对局过滤、跨局检测、无效输入、客户端不兼容、失败恢复和日志写入失败。GitHub Actions 配置不等于已经完成远程 CI 验证。
